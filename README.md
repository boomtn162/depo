# สรุปรายการขนส่ง (Shipment Summary)

เว็บแอปสำหรับอัปโหลดไฟล์ **PDF "ใบนำมอบสินค้าห่อวัตถุ(รวม)"** (หลายรายการต่อไฟล์), **PDF "ใบส่งของ/ใบเสร็จรับเงิน"** (รายชิ้นเดียวต่อไฟล์), หรือ **รูปภาพสกรีนช็อต (.png/.jpg)** ของตารางรายการขนส่ง — **แนบได้ทีละหลายไฟล์พร้อมกัน** แล้วสรุปข้อมูลรวมอัตโนมัติ:

- **น้ำหนักรวม** (กก.)
- **ค่าระวาง + ค่า ธ. รวม** (บาท) — รวมจากทุกไฟล์ที่มีข้อมูลนี้
- **จำนวนรายการ** (จำนวนพัสดุ/ใบส่งของทั้งหมด)
- **จำนวนสินค้ารวม** แยกจาก **จำนวนรถ** (ยานพาหนะ เช่น รถจักรยานยนต์/รถยนต์ ไม่นับรวมในจำนวนสินค้า)
- สรุปแยกตามสถานีปลายทาง (รวมข้ามไฟล์ให้อัตโนมัติหากเป็นสถานีเดียวกัน) และรายการทั้งหมด พร้อมระบุว่าแต่ละแถวมาจากไฟล์ไหน
- ตรวจสอบยอดที่คำนวณกับยอดรวมที่พิมพ์/ระบุอยู่ในเอกสารต้นฉบับโดยอัตโนมัติ
- พิมพ์ผลสรุปเป็น **สลิปขนาด 77×166 มม.** (ปุ่ม "พิมพ์สลิป")

ประมวลผลไฟล์ทั้งหมด**ในเบราว์เซอร์ของผู้ใช้เอง** ไม่มีการอัปโหลดไฟล์ขึ้นเซิร์ฟเวอร์ใดๆ — ไฟล์ PDF อ่านด้วย [pdf.js](https://mozilla.github.io/pdf.js/) และรูปภาพอ่านด้วย OCR ผ่าน [Tesseract.js](https://tesseract.projectnaptha.com/) (ภาษาไทย+อังกฤษ) ทั้งสองไลบรารีแนบมากับโปรเจกต์แล้วเพื่อให้ใช้งานได้แบบออฟไลน์

### อัปโหลดหลายไฟล์พร้อมกัน

เลือก/ลากไฟล์ได้มากกว่า 1 ไฟล์ในครั้งเดียว — ผสมชนิดไฟล์กันได้ (PDF ใบนำมอบสินค้า, PDF ใบส่งของ, รูปภาพ) เว็บแอปจะ:
1. อ่านและแยกวิเคราะห์ทีละไฟล์ (แสดงสถานะ ✓/⚠/✕ ต่อไฟล์ในรายการด้านบนผลสรุป)
2. รวมทุกรายการเป็นตารางเดียว จัดกลุ่มตามชื่อสถานี — สถานีเดียวกันจากคนละไฟล์จะถูกรวมยอดให้อัตโนมัติ
3. แสดงในตารางที่**แก้ไขได้เสมอ** (ไม่ว่าจะมาจาก PDF หรือ OCR) เผื่อพบข้อผิดพลาดจากการอ่านไฟล์

เมื่ออัปโหลดไฟล์ **PDF ใบนำมอบสินค้าห่อวัตถุ(รวม) เพียงไฟล์เดียว** เว็บแอปจะใช้โหมดเดิมที่ตรวจสอบยอดกับเอกสารอย่างเข้มงวด (ตาราง read-only) เหมือนเดิมทุกประการ — ไม่กระทบผู้ใช้เดิม

### เกี่ยวกับความแม่นยำของ OCR (รูปภาพ)

การอ่านข้อความจากรูปภาพด้วย OCR **อาจอ่านตัวเลขผิดพลาดได้** โดยเฉพาะตัวอักษร/ตัวเลขในเลขที่ใบส่งที่ตัวเล็กหรือภาพไม่คมชัด เว็บแอปจึงมีขั้นตอนตรวจสอบ 2 ชั้น:

1. เทียบจำนวนที่คำนวณได้ต่อสถานีกับตัวเลข "(จำนวน N ชิ้น)" ที่ระบุอยู่ในภาพ — สถานีที่ไม่ตรงจะถูกไฮไลต์เตือน
2. ตารางรายการที่อ่านได้ **แก้ไขได้โดยตรง** (น้ำหนัก/จำนวน/ยานพาหนะ/ลบ/เพิ่มรายการ) ยอดสรุปทั้งหมดจะคำนวณใหม่ทันทีเมื่อแก้ไข

**กรุณาตรวจสอบตัวเลขในตารางก่อนเชื่อผลสรุป** โดยเฉพาะก่อนพิมพ์สลิปหรือใช้งานจริง

## วิธีใช้งาน

ต้องเปิดผ่านเว็บเซิร์ฟเวอร์ (ไม่ใช่เปิดไฟล์ index.html ตรงๆ แบบ `file://`) เพราะ pdf.js โหลด worker script ผ่าน HTTP:

```bash
# ตัวอย่าง: เสิร์ฟด้วย Python
python3 -m http.server 8000
# แล้วเปิด http://localhost:8000/
```

หรือจะ deploy ขึ้น static hosting ใดก็ได้ (GitHub Pages, Netlify, Nginx ฯลฯ) เพราะเป็นไฟล์ static ล้วนๆ ไม่มี backend

จากนั้น:
1. อัปโหลด/ลากไฟล์ PDF หรือรูปภาพมาวาง (เลือกได้ทีละหลายไฟล์)
2. (เฉพาะรูปภาพ) รอ OCR อ่านข้อความ — ใช้เวลาประมาณ 10-40 วินาทีขึ้นกับขนาดภาพ แล้ว**ตรวจสอบ/แก้ไขตัวเลขในตารางที่อ่านได้**
3. ดูสรุปยอดรวม + ตารางแยกตามสถานี + รายการทั้งหมด (พร้อมสถานะรายไฟล์เมื่ออัปโหลดหลายไฟล์)
4. กด **"พิมพ์สลิป 77×166 มม."** เพื่อพิมพ์สลิปสรุป (ตั้งค่าเครื่องพิมพ์ให้ตรงกับขนาดกระดาษ 77×166 มม.)

มีไฟล์ตัวอย่างให้ลองใช้งานที่ [`samples/parcel_list_11.pdf`](samples/parcel_list_11.pdf), [`samples/parcel_list_13.pdf`](samples/parcel_list_13.pdf) (มีรถจักรยานยนต์ + แถวที่ไม่มีคำระบุหน่วยสินค้า เป็นกรณีทดสอบขอบเขต) และ [`samples/receipt_1.pdf`](samples/receipt_1.pdf) (ใบส่งของรายชิ้น) — ลองอัปโหลดทั้งสามไฟล์พร้อมกันเพื่อดูการรวมยอดข้ามไฟล์

## โครงสร้างไฟล์

```
index.html            หน้าเว็บหลัก
css/style.css          สไตล์หน้าจอ + สไตล์สลิปสำหรับพิมพ์ (@media print, @page 77mm x166mm)
js/app.js               parser ของทั้ง 3 รูปแบบไฟล์ + ตัวรวมผลหลายไฟล์ (batch), คำนวณยอดรวม, render ผลลัพธ์, ตารางแก้ไขได้
vendor/pdfjs/           ไลบรารี pdf.js (legacy build) สำหรับอ่านไฟล์ PDF แบบออฟไลน์
vendor/tesseract/       ไลบรารี Tesseract.js + ข้อมูลภาษาไทย/อังกฤษ (best_int, บีบอัด) สำหรับ OCR แบบออฟไลน์
samples/                ไฟล์ตัวอย่างสำหรับทดสอบ (PDF ใบนำมอบสินค้า x2, PDF ใบส่งของ x1)
```

## หมายเหตุเรื่องรูปแบบไฟล์

มี parser 3 แบบใน `js/app.js` ตามรูปแบบข้อมูลที่ต่างกัน — `detectPdfKind()` เดารูปแบบไฟล์ PDF จากข้อความในไฟล์โดยอัตโนมัติ:

**`parseManifest`** — ไฟล์ PDF "ใบนำมอบสินค้าห่อวัตถุ(รวม)" (หลายรายการ/หลายสถานีต่อไฟล์):
- แต่ละสถานีปลายทางขึ้นต้นด้วยบรรทัด `รหัสสถานี ชื่อสถานี` (เช่น `1007 ชุมทางบางซื่อ`)
- แต่ละแถวรายการมีคอลัมน์: ลำดับ, เลขที่, จำนวน+หน่วย, รายการ, ค่าระวาง+ค่า ธ., น้ำหนัก(กก.)
- พัสดุที่มีหลายรายการย่อยจะมีแถวต่อท้ายแบบไม่มีลำดับ/เลขที่ (ใช้เลขที่เดียวกับแถวก่อนหน้า)
- อัปโหลด**ไฟล์นี้เพียงไฟล์เดียว** จะได้ตาราง read-only ที่ตรวจสอบยอดกับเอกสารอย่างเข้มงวด; อัปโหลดพร้อมไฟล์อื่นจะเข้าโหมดรวมผล (แก้ไขได้)

**`parseReceiptPdf`** — ไฟล์ PDF "ใบส่งของ/ใบเสร็จรับเงิน" (รายชิ้นเดียวต่อไฟล์):
- เลย์เอาต์ 2 คอลัมน์ (ผู้ส่ง | ผู้รับ) — ดึงค่าด้วย label ที่มีขอบเขตจาก label ถัดไป ไม่ใช่การยึดต้น/ท้ายบรรทัด เพราะ pdf.js รวมข้อความสองฝั่งเป็นบรรทัดเดียวกัน
- ค่าธรรมเนียมแยกเป็นหลายรายการ: ค่าระวาง, ค่าธรรมเนียม (="ค่า ธ." ในไฟล์ใบนำมอบสินค้า), ค่าขนขึ้น/ลง, ค่ารักษา, ส่วนลด, รวมเป็น "รวมเงินทั้งสิ้น" — ฟิลด์ "ค่าระวาง+ค่าธ." ในเว็บนี้ใช้เฉพาะค่าระวาง+ค่าธรรมเนียม 2 ตัวแรกให้นิยามตรงกับไฟล์ใบนำมอบสินค้า
- ตรวจสอบภายในไฟล์เอง (บวกค่าธรรมเนียมทุกรายการเทียบกับ "รวมเงินทั้งสิ้น" ที่พิมพ์ไว้) หากไม่ตรงจะขึ้นสถานะ ⚠ ในรายการไฟล์

**`parseDashboardOcr`** — รูปภาพสกรีนช็อตจากระบบ/หน้าเว็บ (เช่น "ขบวนรถพิเศษสินค้า"):
- แต่ละสถานีขึ้นต้นด้วยบรรทัดชื่อสถานี ตามด้วย `(จำนวน N ชิ้น)` ท้ายบรรทัด — ใช้เป็นตัวเลขตรวจสอบ
- แต่ละรายการย่อยขึ้นต้นด้วย `N. ` ตามด้วยชื่อสินค้า น้ำหนัก และจำนวน (ไม่มีคอลัมน์ค่าระวาง)
- ไม่มีรหัสสถานีตัวเลขแบบ PDF และเลขที่ใบส่งเป็นการเดาแบบ best-effort จากข้อความรอบๆ (อาจว่างได้)

เมื่ออัปโหลดหลายไฟล์ (หรือไฟล์เดียวที่ไม่ใช่ใบนำมอบสินค้า) ทุกแถวจากทุก parser จะถูกแปลงเป็นรูปแบบเดียวกันแล้วรวมเข้าตารางเดียวผ่าน `buildOcrResult()` — จัดกลุ่มสถานีด้วยชื่อสถานี (สถานีรับ สำหรับใบส่งของ) ผ่าน `groupRowsIntoStations()`

หากได้ไฟล์/ภาพจากระบบอื่นที่ไม่ตรงกับสามรูปแบบนี้ อาจต้องปรับ regex ในไฟล์ `js/app.js`
